# SBO model sources

Source files (QC script, reference meshes, animations, textures) of the models in
`gamedir/syndicate/models/`, compiled with the studiomdlPlusPlus compiler
(studiomdlPlusPlus). Every model is one self-contained `.mdl`: no external texture
files (`nameT.mdl`), no sequence-group files (`name01.mdl` ...).

**Status: 83 models in `gamedir/` are built from these sources** (`scripts/modelsrc.py install`;
`installed.json` lists them with their checksums). For those models the sources are the master:
edit the sources, run `verify` and `install`. **The rebuilt models have not been tested in the
game yet.**

The sources were first made by decompiling the original SBO 1.38 model files. The inventory of
those files, the texture renames, the comparison of every rebuilt model with its original and
the engine-limit notes are kept in [`ORIGINAL-FILES.md`](ORIGINAL-FILES.md) (a record, not
regenerated). The original binaries are in the git history before the install commit.

This file is generated by `scripts/modelsrc.py readme`.

## Layout

```
sdk/modelsrc/
  monsters/<model>/           anims/  mesh/  textures/  <model>.qc
  players/<model>/            (models/player/<model>/<model>.mdl)
  weapons/<weapon>/v_/        view model     v_<weapon>.qc
  weapons/<weapon>/w_/        world model    w_<weapon>.qc
  weapons/<weapon>/p_/        player-held model  p_<weapon>.qc
  props/<model>/  misc/<model>/
  installed.json              what `install` put into gamedir/ (checksums, what it replaced)
  ORIGINAL-FILES.md           record of the original files and of the comparison
```

Every model folder is self-contained: `mesh/` (`$cd ".\mesh"`), `textures/` (8-bit BMP,
`$cdtexture ".\textures"`), `anims/` (one SMD per sequence; `name_blend01.smd` ... for blends).
All paths are lower case.

## Pipeline

```bash
scripts/modelsrc.py verify  [model ...]   # compile the sources into scratch and check the result
scripts/modelsrc.py install [model ...]   # compile and put the models into gamedir/
scripts/modelsrc.py package <folder>      # copy the complete models folder to <folder>/syndicate/models
scripts/modelsrc.py readme                # this file
scripts/modelsrc.py build   [model ...]   # decompile models that are not installed (see below)
```

| File | Role |
| --- | --- |
| `scripts/modelsrc.py` | the pipeline (Python 3 standard library only; one process at a time) |
| `scripts/modelsrc_mdl.py` | MDL reader used for the QC files and the comparison |
| `scripts/modelsrc_readme.py` | writes this README |
| `scripts/modelsrc_rules.json` | rules table: folders, texture renames, per-model cases, install lists |

Tools (override with the environment variables): `STUDIOMDL`, default
`studiomdlplusplus` on PATH (used here: `studiomdlplusplus (Oct 12 2026 10:55:22 7818ddb8)`);
`MDLDEC`, default `mdldec` on PATH (only for
`build`). Scratch files go to `build/modelsrc/` (git-ignored).

- **`verify`**: for an installed model, compiles the sources and requires the result to be
  byte-identical to the file in `gamedir/` (*identical*). For a model that is not installed,
  compares the compiled model with the shipped one field by field (see the record for the method).
- **`install`**: compiles each model, compares it with the file in `gamedir/` and replaces that
  file (same name, same path) only when the result is *equivalent* or differs only by an
  *intentional difference* recorded in the rules table; otherwise it refuses and exits with an
  error. It then deletes the external texture and sequence-group files of the models it replaced
  and the files listed in `install_delete`, but never a file that a remaining model's header
  still names. Models in `install_skip` are never installed; a model with stand-in textures is
  only installed when it is listed in `install_stand_ins`.
  It prints every file it replaced or deleted and updates `installed.json`. Running it again
  changes nothing. After editing sources: `verify` shows *differences* for that model (the
  sources no longer give the installed file); `install <model>` then compares the new build
  with the installed file and refuses if they differ in content; `install --accept <model>`
  installs a deliberate change and prints and records the differences.
- **`build`** (decompile) leaves installed models alone, because it would overwrite the master
  sources with a decompile of their own output. It still works for models that are not installed.
- **`package <folder>`**: copies the complete `gamedir/syndicate/models/` folder, byte for byte,
  to `<folder>/syndicate/models/`: a drop-in replacement for the models folder of an install.
  It refuses while any model in the folder needs an external file, is not the installed build,
  or is neither built from the sources nor listed in `install_keep`.

To compile one model by hand (the output goes to the folder given with `-o`):

```bash
studiomdlplusplus sdk/modelsrc/monsters/zgrunt/zgrunt.qc -o /tmp/rebuilt
```

## The models folder

`gamedir/syndicate/models/` is complete and self-sufficient: no model in it needs an external
texture or sequence-group file, and it can replace the models folder of an install as a whole
(`scripts/modelsrc.py package`).

| Files | Origin |
| --- | --- |
| 83 `.mdl` | built from the sources in this tree (table above) |
| `p_wong.mdl` | model shipped as is: intentionally empty model (bare hands) that the game code precaches; shipped as is |
| `player/agent/agent.bmp` | not a model: player model picture for the game's menus, shipped as is |
| `player/agentf/agentf.bmp` | not a model: player model picture for the game's menus, shipped as is |
| `player/hunted/hunted.bmp` | not a model: player model picture for the game's menus, shipped as is |

`p_wong.mdl` is the one model that is not built from sources: it is an intentionally empty model
(no bones, no vertices: the Fist of Legend weapon shows bare hands), the game code precaches it,
so the file must exist, and there is nothing in it to decompile.

## World models (`w_`)

The shipped SBO world models stood upright, came from other games or had no textures, and
several weapons used Half-Life's own files. The `w_` sources of the 19 weapons below are made from the
rotating-weapons plugin's meshes (each mesh taken from
the weapon's `v_` model and straightened). The mesh is turned so that the weapon lies on its side
(longest extent along X, muzzle or blade toward +X in the game, thinnest extent up), centered on
X/Y and lifted so that its lowest point is at Z = 0, the floor the item drops to. In the SMD the
muzzle points toward -Y: the compiler turns every model 90 degrees about Z, so -Y becomes the
entity's forward +X, the direction its angles point (Half-Life's convention). One bone
(`weapon_root`), one-frame `idle`. The minigun is turned to its stable rest (the pose with the
lowest center of mass that is not upside down: rolled 35 degrees, handle up at an angle); of the
chainsaw sword's two blades, the upper one is pivoted about its hilt, which rests on the other
hilt, until its tip touches the floor. Vertex normals that pointed against their triangle's
visible side were turned round (the engine lights by the normals; most of `w_pm66` and parts of
`w_warhammer`, `w_ben`, `w_canon`, `w_katana`, `w_rpg` were lit from behind, so the side facing
up was dark). Edit these sources directly; they are the master.

the mesh lies on Half-Life's grenade (same skeleton, bone `Line02`), with Half-Life's seven
sequences (`idle`, `roll1` and `roll2` for the grenade rolling on the floor, `toss` to `toss4` for
the thrown grenade tumbling; the code picks them by number). The placed tripmine
(`monster_tripmine`) still uses `v_tripmine.mdl`. Not changed: `weapon_wong` (bare fists, no
world model), `weapon_satchel` (`w_weaponbox`, the backpack, also the thrown charge),
`weapon_snark` (`w_sqknest`; `w_squeak` is the live Pitbull).
